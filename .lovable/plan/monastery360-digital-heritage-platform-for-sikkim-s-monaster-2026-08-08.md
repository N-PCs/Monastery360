# Monastery360 — Digital Heritage Platform for Sikkim's Monasteries

Full demo web platform: 360° virtual tours, MapLibre interactive map, digital archives with AI search, multilingual audio guides, and a cultural calendar.

## Architecture

```text
Frontend (Vercel)              Backend (Cloudflare)
-------------------            ------------------------------
React + TanStack Router   -->  Worker API  (/api/*)
Pannellum 360 viewer            |-- D1  (SQL: monasteries, events,
MapLibre GL JS map              |        archives, beacons, bookings)
Audio guide player              |-- R2  (panoramas, audio, PDF scans)
                                |-- Workers AI / provider key (search + TTS)
```

The app in this workspace is the frontend, written so it deploys to Vercel unchanged. The Worker lives in a separate `worker/` folder in the same repo with its own `wrangler.toml`, deployed with `wrangler deploy`. The frontend talks to it only through `VITE_API_BASE_URL`, so nothing about the backend is baked into the UI.

## Repo layout

```text

  routes/                pages
  components/            UI, map, panorama viewer, audio player

```

## API (Cloudflare Worker)

```text
GET  /api/monasteries              list + filters (district, sect, era)
GET  /api/monasteries/:slug        detail incl. tour scenes + R2 asset keys
GET  /api/map/points               geojson for MapLibre
GET  /api/archives?q=              archive list; q -> AI semantic search
GET  /api/events?month=            cultural calendar
POST /api/bookings                 event interest / participation
GET  /api/beacons/:id              beacon/GPS -> nearest guide track
POST /api/tts                      text + language -> audio (cached in R2)
```

D1 stores text, coordinates, calendar entries, and beacon IDs. R2 stores panoramas, audio tracks, and manuscript scans, served via a public R2 domain (zero egress) with the Worker issuing signed URLs for restricted items.

## Pages

```text
/                     Home — hero, featured monasteries, entry to each pillar
/monasteries          Explorer — searchable/filterable grid
/monasteries/$slug    Detail — history, architecture, gallery, tour, audio guide
/tour/$slug           Full-screen 360° panoramic viewer with hotspots
/map                  MapLibre map: markers, clustering, heritage routes
/archives             Manuscripts, murals, documents + AI search
/calendar             Festivals, rituals, events + participation form
/about                Project, stakeholders, preservation mission
```

## Features

**Virtual tours** — Pannellum equirectangular viewer, client-side only. Scene hotspots move between viewpoints (courtyard → prayer hall → murals) and can trigger the narration for that spot.

**Interactive map** — MapLibre GL JS with a free vector basemap (no token), geo-tagged markers, clustering, popup cards linking to detail pages, heritage-circuit route lines, and nearby-attraction pins.

**Digital archives** — Manuscripts, murals, and documents with metadata (era, monastery, language, material). Semantic search: the Worker embeds the query, ranks stored embeddings from D1, and returns matches; AI also generates summaries and category tags.

**Smart audio guide** — Multilingual narration (English, Nepali, Hindi, Bhutia, Lepcha) generated by the Worker's TTS endpoint and cached into R2, so a given text+language is generated once. Persistent mini-player, plus GPS/beacon triggering on the detail page.

**Offline mode** — Service worker caches monastery detail pages, audio tracks, and low-res panoramas for a downloaded monastery so it works in remote areas.

**Cultural calendar** — Month and list views of Losar, Pang Lhabsol, Bumchu, Saga Dawa, cham dances, etc., filterable by monastery, with a participation/RSVP form posting to the Worker.

## Design direction

Himalayan heritage, not generic travel site: deep monastery-red and saffron accents over warm parchment and dark-slate surfaces, gold hairline rules, prayer-flag colors used sparingly, thangka-inspired border motifs, editorial serif headings with a clean sans body. All colors as semantic tokens with light/dark support.

## Build order
